# Long-Term Care Legislative Tracker: Runbook

Page: `/legislation/` (`legislation/index.html`, `Assets/ct-legislative-tracker.js`, `Assets/ct-legislative-threads.js`).

Data:
- `data/ct_ltcop_legislative_tracker.json`: hand-maintained. It holds the session, statuses, topics, current bills and watch list, deadlines, past bills and how-to cards.
- `data/ct_ltcop_legislative_threads.json`: hand-maintained storylines. Each thread lists dated, sourced `events` that point to bills or acts by id (`ref`). Bills carry no thread field; the "Part of" chips are computed from the threads.
- `data/ct_ltcop_act_reference.json`: every long-term care act since 2021, generated by `scripts/build_ct_ltcop_act_reference.py` (edit the `ROWS` table there, then run it).
- `data/ct_ltcop_positions.json`: approved Program positions only. It ships empty; see `docs/ct_ltcop_positions_runbook.md`.
- Each topic in the tracker file has a `background` list (pre-2021 history, 2 to 6 sourced entries).
- `data/ct_legislative_research_stats.json`: generated by `scripts/build_ct_legislative_research_stats.py` from data already on the site (PBJ staffing, the CT statewide context, survey and enforcement, and the LTCOP FFY 2025 impact data).

Rule: listing a bill is research support, not an LTCOP position. Do not add position fields unless the State Ombudsman approves the wording.

## Weekly during the session (Jan 6 to Jun 9, 2027)
1. Open each tracked bill's status page (`bill_status_url`) and update `status`, `last_action` and `last_action_date` in `bills_current`.
   - Status ids: `introduced`, `hearing`, `committee_passed`, `calendar`, `passed_one`, `passed_both`, `signed`, `vetoed`, `failed`.
   - When a bill is signed, add `public_act`, for example `"PA 27-15"`.
2. To add a new bill, use this entry format:
   ```json
   {"id": "2027-sb123", "session": "2027", "bill": "SB 123", "status": "introduced",
    "title": "An Act Concerning ...", "topics": ["staffing_workforce"],
    "summary": "One or two neutral sentences on what it would do.",
    "last_action": "Referred to Aging Committee", "last_action_date": "2027-01-20",
    "bill_status_url": "https://www.cga.ct.gov/asp/cgabillstatus/cgabillstatus.asp?selBillType=Bill&which_year=2027&bill_num=123",
    "related": ["2025-sb1279"]}
   ```
   - Topic ids: `staffing_workforce`, `quality_oversight`, `ownership_finance`, `discharge_rights`, `closures_capacity`, `community_settings`, `ombudsman_program`, `aging_financing`.
   - When a bill replaces a watch-list item, delete the watch item or point the bill's `related` at the past bills.
3. Add committee deadlines and public hearing dates to `deadlines` once the General Assembly publishes them. Each entry needs `date`, `what` and `source_url`.
4. Update `last_updated`, then run `python scripts/validate_ct_legislative_tracker.py`, `python scripts/validate_ct_legislative_threads.py`, `python scripts/test_ct_legislative_tracker.py` and `python scripts/test_ct_legislative_threads.py`.

## After the session
**Storylines.** For each thread in `data/ct_ltcop_legislative_threads.json`:
1. Add the session's events: each 2027 bill that moved on the thread's question (its last action date, `kind: "bill"`, or the act's effective date, `kind: "act"`), with a 12-word `label`, a 30-word `what` and a `source_url` you opened.
2. Set `status`: `active` if the question is still being legislated, `settled` if the session resolved it, `watching` if only a study or report is pending.
3. Update `summary` (60 words or fewer) and `open_questions`, and point `watch` at the next session's watch items.
4. Add every enacted long-term care act to `ROWS` in `scripts/build_ct_ltcop_act_reference.py` (source: OLR's Acts Affecting Seniors report and each act's bill status page), run it, then run `python scripts/validate_ct_legislative_threads.py`.
5. Consider a new thread when three or more bills on one question appear across sessions; drafts are reviewed before publishing.

**Bills.** Move each `bills_current` entry that has a bill number into `bills_past`:
- Set `enacted` to true or false.
- Add `public_act`, `key_dates` and `sources`.
- Drop the `status` field.

Then set the new session dates in `session`.

## When site data refreshes
Run `python scripts/build_nursing_home_ct_statewide_context.py`, then `python scripts/build_ct_legislative_research_stats.py`, then the tests.
- **Accuracy check.** After any data refresh, and again before the session opens on January 6, 2027, repeat the Phase 1 accuracy check: confirm every number and claim in the topics (`why`, `context_facts`, stat labels and displays, `background`, thread events) against its source, and that home counts name their denominator.
- The test pins a few headline numbers: 36 below 3.00, 120 below 3.60, 3,253 complaints.
- Update those numbers only when the source data legitimately changed.
- Add the FFY 2026 LTCOP impact data by pointing the stats builder at the new impact file once it exists.

## Sources and verification
The 2023 to 2026 bill entries were checked on 2026-10-30 against CGA bill status pages, OLR reports and the LTCOP "Advocacy over the years" page; each entry lists its sources.

Open questions are recorded in each entry's `notes`:
- Whether 2026 SB 288 and SB 289 content was carried into other acts.
- The PA 26-72 planning committee report date, which OLR states two ways.
- PA 26-50 training hours, which sources state differently.

A small subset of 2023 to 2025 entries rely on LTCOP's one-line descriptions rather than the act text. Re-read the act before quoting one in testimony.

## Session bill tracker pages (`/legislation/2026/` final, `/legislation/2027/` in progress)
Each session gets one page that shows every bill on the Program's list, its plain summary and its status. The page reads `data/ct_ltcop_bill_tracker_<year>.json` through `Assets/ct-session-tracker.js`, so a new session needs no new code. `/legislation/2027/` already exists and shows a pre-session message until bills are added.

Statuses during the session: `introduced`, `hearing`, `committee_passed`, `passed_one`, `passed_both`, `signed`, `vetoed`. When the session ends, change `introduced` to `no_action` and `hearing` to `hearing_only`. The validator refuses in-progress statuses in a final report.

### Each week during the 2027 session
1. When the Program posts its weekly list, add any new bills to `data/ct_ltcop_bill_tracker_2027.json`. Each needs:
   - `id` such as `2027-sb123`, `bill`, `list` (1 or 2), `title` and `committee`.
   - A neutral `summary` of 35 words or fewer.
   - `status`, `latest_action` and `latest_action_date`.
   - `bill_status_url` with `which_year=2027`.
2. Run `python scripts/ct_session_weekly_report.py 2027`. It lists every bill still moving, oldest recorded action first, with its status-page link. It flags bills with no recorded action in 14 days or more.
3. Open each listed status page and update `status`, `latest_action` and `latest_action_date`. Add `public_act` when a bill is signed.
4. Update `report`:
   - Set `label`, for example `Week of 2/16/2027 (Update 6)`.
   - Set `status_as_of` and `update_number`.
   - Remove `empty_note` once bills are listed.
5. **Tag topics.** Give each new bill an optional `topics` list (the topic ids above). If it belongs to a storyline, add an event to that thread pointing at the bill's id (`ref: "2027-sb123"`) with its latest action date and the bill status page as `source_url`.
6. Run `python scripts/validate_ct_session_tracker.py 2027`, `python scripts/validate_ct_legislative_threads.py` and `python scripts/test_ct_legislative_tracker.py`.
7. Run the weekly report again. Its "Changes since the previous report" section, which compares against the last committed version, is the draft for the weekly post. "Untagged bills" lists bills with no topics or in no storyline; "Moves by storyline" groups the week's status changes by thread.

### After the Governor acts on every bill
1. Update the report and statuses:
   - Set `report.label` to `Final report` and `report.final` to `true`.
   - Convert end-of-session statuses as described above.
   - Add `public_act` numbers.
   - Fill `also_enacted`.
2. Move the session's key bills into `bills_past` on `/legislation/`.
3. Set the next session in `session`.
4. Start `legislation/2028/` by copying the 2027 page and data file. Reset the copied data file: set the 2028 session dates, set `report.label` to `Pre-session` with `final` false, and empty `bills` and `also_enacted`.
5. Link the new page from `/legislation/`.
